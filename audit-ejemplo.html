01. Resumen ejecutivo

En este escenario ficticio, la web es accesible para rastreadores y tiene mapa del sitio, pero no supera 4 de los 7 puntos de preparación para agentes. Además, presenta problemas al exponer información esencial del negocio y no ofrece una forma clara para que un agente complete una reserva. La información publicada tampoco es completamente coherente entre los distintos canales.

Cómo se calcula: puntuación de ejemplo basada en seis áreas con pesos de 15, 20, 15, 15, 15 y 20 puntos, respectivamente. El área de los 7 puntos de preparación para agentes puntúa por igual cada punto: 3 de 7 superados equivalen a 6 de 15 (redondeado). En este caso ficticio: 6 + 3 + 8 + 8 + 8 + 0 = 33. No es una puntuación oficial ni una métrica universal de visibilidad en IA. En una auditoría real, JM20 debe definir y aplicar criterios verificables y consistentes.

02. Alcance y metodología

Una auditoría real debe dejar claro qué se ha revisado, cómo se ha revisado y qué no puede concluirse a partir de esas comprobaciones. Esta auditoría cubre 1 sitio web y hasta 5 páginas.

Preparación para agentes

Los 7 puntos de la comprobación gratuita, explicados uno a uno: rastreo, descubrimiento y señales para agentes.

Contenido e información

Comprobación de que servicios, precios, horarios y contacto están publicados como contenido legible.

Datos y coherencia

Revisión de datos estructurados y comparación de la información del negocio entre canales.

Experiencia y acciones

Inspección de estructura, rendimiento y posibilidades reales de completar tareas, como reservar.

Las pruebas de respuesta de asistentes de IA dependen del sistema, la consulta, la ubicación, el contexto y el momento. Una prueba puntual no demuestra cómo responderán todos los modelos ni garantiza recomendaciones futuras.

03. Los 7 puntos de preparación para agentes

Son los 7 puntos que revisa la comprobación gratuita. Aquí se explica cada uno: qué se revisó, qué se encontró, por qué importa y qué haríamos.

3 superados 4 no superados
01

Archivo robots.txt

Superado
Qué se revisó
Que el archivo /robots.txt exista y responda correctamente.
Hallazgo
El archivo existe, responde con código 200 y se puede leer.
Evidencia de ejemplo
https://barberiaejemplo.es/robots.txt · respuesta HTTP 200. Datos simulados.
Por qué importa
Es el primer sitio donde los rastreadores, incluidos los de IA, buscan instrucciones sobre qué pueden leer.
Qué haríamos
No se requiere un cambio. Lo revisaríamos de nuevo cuando se añadan reglas nuevas.
Prioridad: BajaEstimación: Sin cambiosEstado: Sin acción correctiva
02

Mapa del sitio (sitemap.xml)

Superado
Qué se revisó
Que exista un mapa del sitio con las páginas públicas.
Hallazgo
El archivo /sitemap.xml existe y lista las páginas principales.
Evidencia de ejemplo
https://barberiaejemplo.es/sitemap.xml · respuesta HTTP 200. Datos simulados.
Por qué importa
Ayuda a que los sistemas descubran qué páginas tiene la web.
Qué haríamos
No se requiere un cambio. Convendría mantenerlo actualizado cuando se añadan o eliminen páginas.
Prioridad: BajaEstimación: Sin cambiosEstado: Sin acción correctiva
03

Cabeceras Link

No superado
Qué se revisó
Si la página principal devuelve cabeceras HTTP Link que señalen recursos útiles para agentes (RFC 8288).
Hallazgo
La página principal no devuelve ninguna cabecera Link.
Evidencia de ejemplo
Respuesta HTTP de https://barberiaejemplo.es/ sin cabecera Link. Datos simulados.
Por qué importa
Las cabeceras Link permiten que un agente descubra, sin leer toda la página, dónde hay documentación o descripciones de servicio. Es una práctica emergente: no garantiza que un sistema concreto la utilice.
Qué haríamos
Añadir cabeceras Link en la página principal que apunten a recursos que existan de verdad y comprobarlas después.
Prioridad: MediaEstimación: 30–60 minEstado: Pendiente
04

Contenido en Markdown para agentes

No superado
Qué se revisó
Si, al pedir la página con Accept: text/markdown, el servidor devuelve una versión en Markdown.
Hallazgo
El servidor devuelve siempre HTML, aunque se pida Markdown.
Evidencia de ejemplo
Petición con Accept: text/markdown · respuesta con Content-Type: text/html. Datos simulados.
Por qué importa
Un formato ligero puede ser más fácil de leer para un agente que el HTML completo. Es una práctica emergente y no todos los sistemas la utilizan.
Qué haríamos
Si el proveedor de la web ofrece esta opción, activarla; si no, implementarla manteniendo el HTML para los navegadores. Comprobar el resultado.
Prioridad: MediaEstimación: 1–2 horasEstado: Pendiente
05

Reglas para rastreadores de IA

Superado
Qué se revisó
Que robots.txt defina reglas para los rastreadores de IA o para todos los rastreadores.
Hallazgo
El archivo define reglas para los rastreadores y no bloquea a los de IA contemplados en esta comprobación.
Evidencia de ejemplo
Reglas User-agent en https://barberiaejemplo.es/robots.txt. Datos simulados.
Por qué importa
Decide qué sistemas de IA pueden leer la web. Conviene que sea una decisión del negocio y no un resultado accidental.
Qué haríamos
No se requiere un cambio. Revisaríamos las reglas si el negocio cambia de política.
Prioridad: BajaEstimación: Sin cambiosEstado: Sin acción correctiva
06

Señales de uso de contenido

No superado
Qué se revisó
Si robots.txt declara cómo puede usarse el contenido (búsqueda, respuestas de IA o entrenamiento) mediante la directiva Content-Signal.
Hallazgo
No hay ninguna directiva Content-Signal en robots.txt.
Evidencia de ejemplo
robots.txt sin línea Content-Signal. Datos simulados.
Por qué importa
Permite declarar de forma explícita la preferencia del negocio sobre el uso de su contenido. Es una propuesta de Cloudflare y no todos los sistemas la respetan.
Qué haríamos
Añadir una línea Content-Signal con la política que decida el negocio, por ejemplo: Content-Signal: search=yes, ai-input=yes, ai-train=no.
Prioridad: BajaEstimación: 15–30 minEstado: Pendiente
07

Índice de Agent Skills

No superado
Qué se revisó
Si existe un índice de Agent Skills en /.well-known/agent-skills/index.json.
Hallazgo
El archivo no existe (respuesta 404).
Evidencia de ejemplo
https://barberiaejemplo.es/.well-known/agent-skills/index.json · respuesta HTTP 404. Datos simulados.
Por qué importa
Un índice de skills permite que un agente cargue instrucciones sobre cómo consultar o usar el negocio. Es un borrador en evolución y no garantiza ningún comportamiento.
Qué haríamos
Publicar el índice con una skill que describa el negocio (servicios, horarios y cómo reservar), con su huella (digest) verificada.
Prioridad: MediaEstimación: 1–2 horasEstado: Pendiente

04. Resultados por área de negocio

Más allá de los puntos técnicos, estas áreas revisan si la información del negocio es clara, coherente y utilizable por una IA.

01

Datos del negocio legibles

Crítica · 3/20
Qué se revisó
Presentación de horarios, servicios, precios, dirección y datos de contacto en las páginas públicas.
Hallazgo
Los horarios están publicados dentro de una imagen y la lista de precios aparece en un PDF escaneado. La página principal no contiene una versión textual completa de esa información.
Evidencia de ejemplo
/assets/horarios.jpg · /documentos/precios.pdf · ausencia de una tabla HTML de precios en /servicios/. Rutas y observaciones simuladas.
Por qué importa
El texto incluido en imágenes o documentos escaneados puede no estar disponible para todos los sistemas de extracción. Esto puede dificultar que un asistente identifique con precisión qué servicios ofrece el negocio, cuánto cuestan o cuándo abre.
Qué haríamos
  • Publicar horarios como texto HTML.
  • Crear una página de servicios y precios con contenido seleccionable.
  • Añadir dirección, teléfono y datos de contacto en un lugar visible.
  • Mantener la información consistente en todas las páginas.
Prioridad: AltaEstimación: 1–2 horasEstado: Pendiente
02

Datos estructurados

Mejorable · 8/15
Qué se revisó
Presencia y consistencia de datos estructurados basados en Schema.org, especialmente información de negocio local.
Hallazgo
La web incluye el nombre del negocio en el marcado, pero no declara de forma completa y coherente la dirección, los horarios, el teléfono y los servicios.
Evidencia de ejemplo
Inspección simulada del código fuente de la página principal: entidad de negocio incompleta; propiedades openingHours, telephone y address ausentes o incompletas.
Por qué importa
Los datos estructurados ayudan a describir entidades y propiedades de forma explícita. No garantizan que un sistema de IA los utilice ni que una web obtenga una posición o recomendación determinada.
Qué haríamos
Implementar y validar un marcado apropiado para el negocio local, con datos reales y consistentes. Añadir únicamente propiedades que puedan verificarse en el contenido visible de la web.
Prioridad: MediaEstimación: 1–2 horasEstado: Pendiente
03

Coherencia de datos externos

Mejorable · 8/15
Qué se revisó
Coincidencia de nombre, dirección, teléfono y horarios entre la web y perfiles externos seleccionados.
Hallazgo
En este ejemplo, el teléfono publicado en la web no coincide con el de Apple Maps y el horario del sábado difiere entre la web y el perfil de Google.
Evidencia de ejemplo
Web: 910 000 111 · ficha externa: 910 000 222. Sábado en web: 10:00–14:00 · ficha externa: 10:00–15:00. Todos los datos son inventados.
Por qué importa
Las diferencias entre fuentes pueden generar incertidumbre sobre cuál es la información correcta. Conviene que los datos principales sean precisos y estén actualizados en los canales relevantes.
Qué haríamos
Confirmar los datos correctos con el negocio y unificar teléfono, dirección y horarios en la web y en los perfiles externos que controle el cliente.
Prioridad: MediaEstimación: 1 hora + actualización de perfilesEstado: Pendiente de confirmar datos reales
04

Estructura y rendimiento

Mejorable · 8/15
Qué se revisó
Estructura de encabezados, títulos de página, enlaces internos y rendimiento de carga en móvil.
Hallazgo
Varias páginas utilizan el mismo título HTML y la página principal presenta imágenes de gran tamaño que ralentizan la carga en el escenario simulado.
Evidencia de ejemplo
<title>Barbería Ejemplo</title> repetido en tres páginas. Imágenes principales sin compresión adecuada. No se aportan métricas reales de laboratorio ni de usuarios.
Por qué importa
Una estructura clara facilita que personas y sistemas automáticos identifiquen el propósito de cada página. El rendimiento también influye en la experiencia de navegación, aunque no debe confundirse una mejora de velocidad con una garantía de visibilidad en IA.
Qué haríamos
Asignar títulos descriptivos y únicos, ordenar encabezados, revisar enlaces internos y optimizar el tamaño y formato de las imágenes. Medir el resultado antes y después con herramientas de rendimiento.
Prioridad: MediaEstimación: 2–3 horasEstado: Pendiente
05

Acciones disponibles para agentes

Crítica · 0/20
Qué se revisó
Si un usuario o agente puede completar una tarea útil en la web, en este caso consultar disponibilidad y solicitar una reserva.
Hallazgo
Las reservas se gestionan por teléfono o mediante un formulario web convencional. En este escenario, no existe una interfaz de acción documentada y comprobada que permita a un agente consultar disponibilidad y tramitar una reserva de forma estructurada.
Evidencia de ejemplo
Enlace de teléfono y formulario HTML estándar en /reservas/. No se ha identificado una integración de reservas compatible con agentes. Comprobación ficticia.
Por qué importa
Que una IA pueda leer una página no significa que pueda completar una operación. Para ejecutar una reserva se necesita una integración funcional, acceso a disponibilidad actualizada y controles adecuados antes de confirmar la operación.
Qué haríamos
Evaluar la plataforma de reservas y, si es técnicamente viable, implementar una vía de interacción compatible con agentes —por ejemplo, mediante WebMCP— conectada al sistema de reservas. La solución debe validar disponibilidad, respetar las reglas del negocio y solicitar confirmación antes de cerrar la reserva.
Prioridad: AltaEstimación: Depende del sistema de reservasEstado: Requiere análisis de integración

05. Otras áreas que podrían aplicar a tu web

Además de los 7 puntos anteriores, existen otros estándares de preparación para agentes. No todos tienen sentido para todas las webs: los marcamos solo cuando encajan con el negocio. Muchos son borradores o propuestas recientes, por lo que no garantizan ninguna recomendación.

ÁreaCuándo tiene sentidoEn este ejemplo
WebMCPWebs donde un agente puede hacer acciones, como reservar o pedir presupuesto. Es una propuesta de estándar con soporte inicial en Chrome.Recomendado
Catálogo de API (RFC 9727)Webs con APIs públicas que quieren que los agentes las descubran.No necesario
Descubrimiento OAuth/OIDCWebs con APIs protegidas mediante inicio de sesión.No necesario
Metadatos de recurso protegido OAuthWebs con APIs protegidas que quieren indicar a los agentes cómo autenticarse.No necesario
Auth.mdWebs que permiten registrar agentes para usar sus servicios.No necesario
Tarjeta de servidor MCPWebs que ofrecen un servidor MCP propio. Es un estándar aún en elaboración.No necesario
Tarjeta de agente (A2A)Webs que ofrecen un agente propio con el que otros agentes puedan comunicarse.No necesario
Manifiesto de capacidades (ARD)Webs con varias capacidades para agentes (servidores MCP, agentes A2A, esquemas OpenAPI) que quieren listarlas en un solo sitio.No necesario por ahora
DNS para descubrimiento de IA (DNS-AID)Empresas con servicios para agentes que controlan su DNS. Es un borrador del IETF.No necesario
Web Bot AuthWebs que envían peticiones como bot o agente y quieren identificarse ante otros sitios.No necesario
Protocolo de agente personal (Poppy)Solo para webs con ese caso de uso concreto.No necesario
